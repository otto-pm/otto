# Otto: AI-Powered Project Management Solution

![Otto Logo](https://raw.githubusercontent.com/otto-pm/otto/main/docs/assets/otto_logo.png) <!-- Placeholder for a logo, assuming one exists or will be created -->

## 1. Project Title and Description

**Otto** is an advanced **AI-Powered Project Management Solution** designed to streamline development workflows, enhance code understanding, and automate documentation generation. Leveraging sophisticated AI models and RAG (Retrieval Augmented Generation) techniques, Otto integrates seamlessly with your existing code repositories, providing intelligent insights, generating comprehensive documentation, and facilitating efficient project oversight.

Built with a modular architecture, Otto aims to reduce cognitive load for developers and project managers by automating repetitive tasks, ensuring up-to-date documentation, and offering an intelligent interface to query codebase specifics.

## 2. Features

Otto offers a robust set of features to empower your development team:

*   **AI-Powered Documentation Generation**: Automatically generate various types of documentation (API, user guides, technical specifications, READMEs) for specific code targets (functions, classes, methods) within your repository.
*   **Intelligent Code Ingestion & Chunking**: Utilizes advanced code parsing and chunking techniques (e.g., `EnhancedCodeChunker`) to understand the structure and context of your codebase, including class methods, imports, and relationships.
*   **GitHub Integration**:
    *   Push generated documentation directly to your GitHub repository.
    *   Optionally create pull requests for review and merging.
    *   Manage repository access and permissions for secure operations.
*   **Local File Management**: Save generated documentation and edited code locally for review before pushing to remote repositories.
*   **Flexible Documentation Types**: Supports generation for `api`, `user_guide`, `technical`, and `readme` documentation formats.
*   **Scalable Backend Services**: A FastAPI-based backend provides a robust API for interacting with Otto's core functionalities.
*   **User Authentication & Authorization**: Secure access to features with user authentication and repository-level access verification.
*   **Real-time Output Streaming**: Option to stream documentation generation progress for immediate feedback.

## 3. Installation

To set up Otto locally, you'll need Python 3.9+ and `pip`. This project consists of multiple services (e.g., `ingest-service`, `backend`).

### Prerequisites

*   Python 3.9+
*   `pip` (Python package installer)
*   Git
*   A GitHub Personal Access Token (PAT) with `repo` scope for repository interactions.

### Steps

1.  **Clone the Repository**:
    ```bash
    git clone https://github.com/otto-pm/otto.git
    cd otto
    ```

2.  **Set up Virtual Environments**:
    It's recommended to use separate virtual environments for each service.

    ```bash
    # For ingest-service
    cd ingest-service
    python -m venv venv
    source venv/bin/activate  # On Windows: venv\Scripts\activate
    pip install -r requirements.txt
    deactivate
    cd ..

    # For backend service
    cd backend
    python -m venv venv
    source venv/bin/activate  # On Windows: venv\Scripts\activate
    pip install -r requirements.txt
    deactivate
    cd ..
    ```

3.  **Configure Environment Variables**:
    Create a `.env` file in the root directory of each service (e.g., `ingest-service/.env`, `backend/.env`) or set them globally.

    Example `.env` for `backend` and `ingest-service`:

    ```env
    # Required for GitHub integration
    GITHUB_TOKEN="YOUR_GITHUB_PERSONAL_ACCESS_TOKEN"

    # Optional: For local output management
    OUTPUT_DIR="./output"

    # Optional: If using Google Cloud Storage (inferred from backend/app/routes/rag.py)
    # GOOGLE_APPLICATION_CREDENTIALS="/path/to/your/gcp-key.json"
    # PROJECT_ID="your-gcp-project-id"
    # BUCKET_RAW="your-raw-bucket-name"
    # BUCKET_PROCESSED="your-processed-bucket-name"

    # For backend service
    SECRET_KEY="YOUR_FASTAPI_SECRET_KEY" # For JWT/session management
    ALGORITHM="HS256"
    ACCESS_TOKEN_EXPIRE_MINUTES=30
    ```
    Replace placeholder values with your actual credentials and desired settings.

## 4. Usage

Otto operates as a set of interconnected services. The primary way to interact with its features is through its RESTful API.

### Starting the Services

1.  **Start the Ingest Service (if standalone processing is needed or for specific internal calls)**:
    (Details for running this service directly are not fully provided in chunks, but it's an internal component. For API interaction, the backend service orchestrates it.)

2.  **Start the Backend API Service**:
    Navigate to the `backend` directory, activate its virtual environment, and run the FastAPI application.

    ```bash
    cd backend
    source venv/bin/activate
    uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
    ```
    The API will be available at `http://localhost:8000`.

### Example: Generating Documentation via API

You can use `curl` or any API client (like Postman, Insomnia) to interact with the API.

**Endpoint**: `POST /docs/generate`

**Authentication**: Requires a Bearer Token (JWT) in the `Authorization` header. You would typically obtain this token through a login endpoint (not shown in provided chunks).

**Request Body Example**:

```json
{
  "repo_full_name": "otto-pm/otto",
  "target": "ingest-service/src/rag/rag_services.py::generate_documentation",
  "doc_type": "api",
  "stream": false,
  "push_to_github": true,
  "save_local": true
}
```

**Curl Command Example**:

```bash
curl -X POST "http://localhost:8000/docs/generate" \
     -H "Content-Type: application/json" \
     -H "Authorization: Bearer YOUR_AUTH_TOKEN" \
     -d '{
           "repo_full_name": "otto-pm/otto",
           "target": "ingest-service/src/rag/rag_services.py::generate_documentation",
           "doc_type": "api",
           "stream": false,
           "push_to_github": true,
           "save_local": true
         }'
```

This request would instruct Otto to generate API documentation for the `generate_documentation` function within the specified file in the `otto-pm/otto` repository, save it locally, and push it to GitHub (potentially creating a PR).
