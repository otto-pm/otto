# otto-pm/otto

An AI Powered Project Management Solution

![Otto Logo](https://example.com/otto-logo.png) <!-- Placeholder for a project logo -->

## 1. Project Title and Description

**Otto** is an advanced AI-powered project management solution designed to streamline development workflows, enhance code understanding, and automate documentation generation. Leveraging sophisticated RAG (Retrieval-Augmented Generation) techniques, Otto intelligently analyzes codebases, provides insightful answers to developer queries, and generates comprehensive, professional documentation for various purposes.

This repository (`otto-pm/otto`) contains the core services and backend components that power Otto, primarily focusing on the ingestion, RAG, and documentation generation capabilities.

## 2. Features

Otto offers a robust set of features to empower development teams:

*   **AI-Powered Documentation Generation**:
    *   Automatically generates high-quality documentation for code (API, technical, user guides, READMEs) based on code context and structure.
    *   Supports various documentation types, adaptable to project needs.
    *   Option to stream documentation generation for real-time feedback.
*   **Intelligent Code Analysis & RAG**:
    *   Utilizes an `EnhancedCodeChunker` to deeply understand code structure, including Python class methods, imports, and relationships.
    *   Performs semantic search over codebases to retrieve relevant chunks for documentation or Q&A.
    *   Provides a powerful RAG backend for asking questions about the codebase.
*   **Seamless GitHub Integration**:
    *   Directly pushes generated documentation to specified GitHub repositories.
    *   Automates the creation of new branches and Pull Requests (PRs) for documentation updates, ensuring version control and review processes.
    *   Fetches repository content and manages user access permissions.
*   **Local File Management**:
    *   Ability to save generated documentation and edited code locally to a configurable output directory.
    *   Organizes saved files by documentation type and timestamp for easy access.
*   **Scalable Backend API**:
    *   A FastAPI-based backend provides a robust API for managing RAG operations, including repository ingestion, processing, embedding, and documentation generation.
    *   Includes user authentication and GitHub token management for secure operations.
*   **Cloud Storage Integration**:
    *   Integrates with Google Cloud Storage (GCS) for efficient management and storage of raw and processed repository data, ensuring scalability and data persistence.

## 3. Installation

To set up and run Otto's backend and ingestion services, follow these steps:

### Prerequisites

*   Python 3.9+
*   `pip` (Python package installer)
*   Git
*   A GitHub account with a Personal Access Token (PAT) with `repo` scope.
*   A Google Cloud Project with billing enabled and credentials configured for Google Cloud Storage access.

### Steps

1.  **Clone the Repository**:
    ```bash
    git clone https://github.com/otto-pm/otto.git
    cd otto
    ```

2.  **Set up Virtual Environment**:
    It's recommended to use a virtual environment to manage dependencies.
    ```bash
    python -m venv venv
    source venv/bin/activate  # On Windows, use `venv\Scripts\activate`
    ```

3.  **Install Dependencies**:
    Navigate to the `backend` and `ingest-service` directories and install their respective dependencies.
    ```bash
    # For backend service
    cd backend
    pip install -r requirements.txt
    cd ..

    # For ingest service
    cd ingest-service
    pip install -r requirements.txt
    cd ..
    ```
    *(Note: You might need to combine `requirements.txt` files or manage them separately if running services independently.)*

4.  **Configure Environment Variables**:
    Create a `.env` file in the root of your project or set environment variables directly.

    ```ini
    # .env example
    GITHUB_TOKEN="YOUR_GITHUB_PERSONAL_ACCESS_TOKEN"
    GCP_PROJECT_ID="your-gcp-project-id"
    BUCKET_RAW="your-gcs-raw-bucket-name"
    BUCKET_PROCESSED="your-gcs-processed-bucket-name"
    # Optional: For local output
    OUTPUT_DIR="./output"
    # Optional: AI model API keys if not using GCP defaults
    # OPENAI_API_KEY="sk-..."
    # GOOGLE_API_KEY="AIza..."
    ```
    *   `GITHUB_TOKEN`: Your GitHub Personal Access Token with `repo` scope.
    *   `GCP_PROJECT_ID`: Your Google Cloud Project ID.
    *   `BUCKET_RAW`: The name of your Google Cloud Storage bucket for raw repository data.
    *   `BUCKET_PROCESSED`: The name of your Google Cloud Storage bucket for processed data.
    *   `OUTPUT_DIR`: (Optional) The local directory where documentation and code will be saved. Defaults to `./output`.

5.  **Google Cloud Authentication**:
    Ensure your Google Cloud credentials are set up. This typically involves:
    ```bash
    gcloud auth application-default login
    ```
    Or setting the `GOOGLE_APPLICATION_CREDENTIALS` environment variable to the path of your service account key file.

## 4. Usage

Otto's core functionality is exposed via its backend API. Here's how you can interact with it, focusing on documentation generation.

### Running the Backend Service

To start the FastAPI backend service:

```bash
cd backend
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```
The API will be available at `http://localhost:8000`.

### Generating Documentation via API

The primary way to generate documentation is through the `/docs/generate` API endpoint.

**Endpoint**: `POST /docs/generate`

**Example Request (using `curl`)**:

```bash
curl -X POST "http://localhost:8000/docs/generate" \
-H "Content-Type: application/json" \
-H "Authorization: Bearer YOUR_AUTH_TOKEN" \
-d '{
  "repo_full_name": "otto-pm/otto",
  "target": "ingest-service/src/rag/rag_services.py::generate_documentation",
  "doc_type": "api",
  "stream": false,
  "push_to_github": true,
  "save_local": true
}'
```

**Parameters**:

*   `repo_full_name` (string, **required**): The full name of the GitHub repository (e.g., "otto-pm/otto").
*   `target` (string, **required**): The specific code entity to document. This can be a file path, a class, or a function (e.g., `"ingest-service/src/rag/rag_services.py::generate_documentation"`).
*   `doc_type` (string, optional): The type of documentation to generate.
    *   Allowed values: `"api"`, `"user_guide"`, `"technical"`, `"readme"`.
    *   Default: `"api"`.
*   `stream` (boolean, optional): If `true`, the documentation generation will stream partial results.
    *   Default: `false`.
*   `push_to_github` (boolean, optional): If `true`, the generated documentation will be pushed to a new branch on GitHub and a Pull Request will be created.
    *   Requires a configured `GITHUB_TOKEN` and appropriate repository permissions.
    *   Default: `false`.
*   `save_local` (boolean, optional): If `true`, the generated documentation will be saved to the local `OUTPUT_DIR`.
    *   Default: `true`.

### Other RAG Operations

While the provided chunks focus on documentation, the backend also supports:

*   **Repository Ingestion**: Processing and chunking a GitHub repository for RAG.
*   **Embedding**: Generating embeddings for code chunks.
*   **Question Answering**: Asking natural language questions about the codebase.

These operations would typically have their own API endpoints (e.g., `/ingest`, `/ask`) within the `backend/app/routes/rag.py` module.
