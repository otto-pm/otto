# Otto: An AI-Powered Project Management Solution

![Otto Logo](https://via.placeholder.com/150/007bff/ffffff?text=Otto) <!-- Placeholder for a project logo -->

Otto is an advanced AI-powered project management solution designed to streamline development workflows, enhance collaboration, and automate tedious tasks. Leveraging cutting-edge AI, Otto provides intelligent assistance for code understanding, documentation generation, and project insights, empowering teams to deliver high-quality software faster.

## 🚀 Project Title and Description

**Project Title:** Otto: AI-Powered Project Management

**Description:** Otto is a comprehensive, AI-driven platform that integrates seamlessly into your development lifecycle. From automatically generating professional documentation for your codebase to providing intelligent insights and managing project tasks, Otto aims to be your team's indispensable AI assistant. Built with a robust Python backend for AI services and a responsive TypeScript frontend, Otto is engineered for performance, scalability, and developer experience.

## ✨ Features

Otto offers a suite of powerful features designed to boost productivity and improve code quality:

*   **Intelligent Documentation Generation:**
    *   Automatically generate various types of documentation (API, User Guide, Technical, README) for functions, classes, and methods within your codebase.
    *   Supports multiple programming languages (e.g., Python, with extensible support for others).
    *   Context-aware documentation based on code analysis and RAG (Retrieval Augmented Generation) techniques.
*   **GitHub Integration:**
    *   Seamlessly push generated documentation directly to your GitHub repositories.
    *   Option to automatically create new branches and Pull Requests (PRs) for documentation updates.
    *   Supports `README.md` updates and dedicated `docs/` directories for other documentation types.
*   **Local File Management:**
    *   Option to save generated documentation locally for review before pushing to Git.
    *   Organized output directory structure for different documentation types.
*   **Code Analysis & Understanding:**
    *   Advanced code chunking and parsing to understand the structure of your codebase (e.g., extracting class methods, imports, file context).
    *   Powers the AI's ability to generate accurate and relevant documentation.
*   **Scalable Backend Services:**
    *   Utilizes a Python-based `ingest-service` for core AI functionalities like RAG and documentation generation.
    *   Exposes functionalities via a FastAPI backend, ensuring high performance and ease of integration.
*   **User & Repository Access Control:**
    *   Securely manages user authentication and GitHub repository access permissions.
    *   Ensures documentation is pushed only to authorized repositories by authorized users.
*   **Streamlined Workflow:**
    *   Automates the often time-consuming and manual process of writing and updating documentation.
    *   Reduces technical debt and improves onboarding for new team members.

## 🛠️ Installation

To get Otto up and running, you'll need to set up both the backend services (Python) and potentially the frontend (TypeScript, if available).

### Prerequisites

*   Python 3.9+
*   Node.js (LTS version) & npm/yarn (for TypeScript frontend, if applicable)
*   Git
*   Docker (recommended for production deployment)
*   A GitHub account and a Personal Access Token with appropriate repository permissions (for GitHub integration).
*   Google Cloud Project (if using Google Cloud Storage for RAG data).

### 1. Clone the Repository

```bash
git clone https://github.com/otto-pm/otto.git
cd otto
```

### 2. Backend (Python Services) Setup

The core AI and API services are written in Python.

```bash
# Create and activate a virtual environment
python3 -m venv venv
source venv/bin/activate # On Windows use `venv\Scripts\activate`

# Install Python dependencies
pip install -r requirements.txt # Ensure requirements.txt exists in the root or relevant service directory (e.g., ingest-service/requirements.txt, backend/requirements.txt)
```

**Note:** You might need to install dependencies for `ingest-service` and `backend` separately if they have their own `requirements.txt` files.

### 3. Frontend (TypeScript) Setup (Optional, if applicable)

If Otto includes a TypeScript frontend, navigate to its directory and install dependencies:

```bash
# Example: If frontend is in a 'frontend' directory
# cd frontend
# npm install # or yarn install
# cd ..
```

### 4. Configuration

Create a `.env` file in the root of your project (or in the respective service directories) based on a `.env.example` (if provided). Essential configurations include:

```env
# .env example for backend/ingest-service
GITHUB_TOKEN="YOUR_GITHUB_PERSONAL_ACCESS_TOKEN"
GOOGLE_CLOUD_PROJECT_ID="your-gcp-project-id"
GCS_BUCKET_PROCESSED="your-processed-data-bucket"
GCS_BUCKET_RAW="your-raw-data-bucket"
# Add any other necessary environment variables for database, LLM APIs, etc.
```

### 5. Running the Services

#### Backend API (FastAPI)

```bash
# From the project root, assuming the backend app is in backend/app/main.py
uvicorn backend.app.main:app --reload --host 0.0.0.0 --port 8000
```

#### Ingest Service (if run independently)

The ingest service might be called by the backend or run as a separate worker. Specific instructions would depend on its design.

## 🚀 Usage

Otto's primary interaction point for documentation generation is through its backend API. Once the backend service is running, you can make API calls to generate and manage documentation.

### Generating Documentation via API

The main endpoint for generating documentation is `/api/docs/generate`.

**Endpoint:** `POST /api/docs/generate`

**Request Body Example:**

```json
{
  "target": "generate_documentation",
  "repo_full_name": "otto-pm/otto",
  "doc_type": "api",
  "stream": false,
  "push_to_github": true,
  "save_local": true
}
```

**Example `curl` Command:**

```bash
curl -X POST "http://localhost:8000/api/docs/generate" \
     -H "Content-Type: application/json" \
     -H "Authorization: Bearer YOUR_USER_AUTH_TOKEN" \
     -d '{
           "target": "generate_documentation",
           "repo_full_name": "otto-pm/otto",
           "doc_type": "api",
           "stream": false,
           "push_to_github": true,
           "save_local": true
         }'
```

**Explanation of Parameters:**

*   `target`: The specific code entity (e.g., function name, class name) for which to generate documentation.
*   `repo_full_name`: The full name of the GitHub repository (e.g., `owner/repo_name`).
*   `doc_type`: The type of documentation to generate. See API Reference for supported types.
*   `stream`: (Optional) If `true`, the response might be streamed (e.g., for real-time updates). Defaults to `false`.
*   `push_to_github`: (Optional) If `true`, the generated documentation will be pushed to the specified GitHub repository. Defaults to `false`.
*   `save_local`: (Optional) If `true`, the generated documentation will also be saved to the local `output` directory. Defaults to `true`.

### Local Documentation Output

If `save_local` is `true`, documentation will be saved in the `./output/documentation/{doc_type}/` directory relative to where the `ingest-service` is run.

Example path: `./output/documentation/api/generate-documentation-20231027103045.md`
